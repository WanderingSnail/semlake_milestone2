# SemLake：面向数据湖仓的零拷贝分支与三路语义合并
## 基于删除向量的谓词级冲突验证及其在智能体工作负载中的拓展

**作者：Xiaofan Cao（Qatar University）**

---

## 摘要

云端数据湖仓通过跨快照共享不可变的 Parquet 清单支持零拷贝分支，但其分支合并机制仍受制于底层物理存储单元。现有系统仅在文件或行标识符粒度检查冲突：对共享文件内不相交行的并发修改会触发虚假回滚或引发整文件写时复制（Copy-on-Write）重写，而跨文件的读写冲突（例如并发执行的数据擦除与分析聚合查询）却被静默放行并污染结果。与此同时，编程语言领域的三路语义合并运行于内存抽象语法树之上，数据库谓词锁则面向短生命周期交互式事务，二者均难以直接迁移至云对象存储上的十亿行级大表，因为在合并阶段扫描底层数据文件会带来高昂的 I/O 与 API 请求开销。

本文提出 **SemLake**，一个无需重写基础 Parquet 文件即可在分支表快照上执行谓词级三路语义合并的湖仓存储与目录架构。SemLake 将元数据阶段的冲突验证与物理数据对齐解耦：每次分支提交记录一个紧凑摘要，包含 SQL 读写谓词、模式变更、被删行的删除前像以及修改行的分叉与顶端值；物理更新则编译为位置 Roaring 删除向量的位图并集。在有限的单机学术资源下，我们构建了融合真实 Parquet/Roaring 位图 I/O、TPC-H SF 1 与 SF 10 下的 DuckDB 分析扫描、1,000 文件真实 Amazon S3 基准测试、原生 Dolt/`delta-rs` 交叉验证以及多智能体离散事件仿真的完整原型。实验表明：(1) 基于提交摘要的双层验证在 34 个标注测试场景与 77 组 TPC-H 分支对上捕获了全部声明的读-删、读-改、外键与值域冲突（召回率与精确率均为 1.00）；(2) Roaring 删除向量并集消除了共享文件虚假回滚，在 SF 1 下局部更新的合并后扫描开销仅为 +0.9%；(3) 在 10,000 文件表上合并仅发起 7 次 S3 请求（在 1,000 文件真实 S3 上耗时 1.76 s，而写时复制耗时 472 s）；(4) 组提交将 64 智能体集群的合并吞吐提升至 17.1 commits/s，且已提交危害数为 0。

## 1 引言 (Introduction)

云端数据湖仓 [6, 21, 23, 40] 将计算引擎与云对象存储（如 AWS S3）解耦，在不可变的 Parquet 文件之上提供事务性表快照。为了隔离数据工程作业、写入-审计-发布（WAP）质量门禁、合规数据清理以及协同分析，数据集版本控制系统 [7, 8, 22, 29, 39] 与零拷贝湖仓目录 [18, 19, 30, 36] 允许用户通过复制元数据指针在毫秒内分叉表快照，在独立分支上执行转换，并将验证后的分支合并回 `main` 主干。

由于不可变的 Parquet 文件可在不同快照间共享 [8]，在云对象存储上创建分支的开销极低。然而，合并两个已分化的表分支在湖仓规模下仍缺乏完备的正确性模型。在生产数据湖仓中，并发分支围绕四类常见工作负载模式发生交互：
- **$W_1$（共享文件不相交更新）**：并发分支更新或删除同一个数百兆字节 Parquet 文件中互不重叠的行。
- **$W_2$（热点主键碰撞）**：并发分支在不同争用密度 $\rho$ 下修改重叠的主键或单元格，需要在不触发回滚风暴的前提下实现结构化冲突隔离。
- **$W_3$（语义依赖）**：一个分支删除或修改某批记录（例如合规擦除或脏数据清理），而并发分支恰好读取了这批记录以计算聚合指标或断言不变式，并将输出写入不相交的文件。
- **$W_4$（模式演化与清单规模）**：一个分支演进表模式，而并发分支在深层文件清单与多跳提交 DAG 上追加数据。

现有开放表格式与版本化数据库仅在物理文件粒度或行标识符粒度评估冲突，在 $W_1$–$W_4$ 上各有局限。在文件级乐观并发控制（$B_1$）[6] 下，$W_1$ 会触发虚假冲突回滚；写时复制行合并（$B_2$）[36] 与元组字典版本控制（$B_3$）[22, 29] 则在 $W_4$ 上引发严重写放大或 $O(N_{\text{files}})$ 次 S3 请求。在 $W_2$ 上，现有引擎要么回滚整个分支（$B_1$–$B_3$），要么通过最后写入者胜出（LWW）的 CRDT 静默覆盖碰撞单元格（$B_4$）[17]。更为关键的是，所有文件级、行级与单元格级引擎（$B_1$–$B_4$ 及 Dolt [14]）在 $W_3$ 上均会漏检：当合规分支 $T_A$ 在基础文件中删除 VIP 记录，而分析分支 $T_B$ 对同批记录汇总营收并写入新文件时，修改的文件集与行 ID 完全不相交，导致现有系统静默提交不一致的快照。

在编程语言（PL）领域，三路结构化与语义合并已通过验证条件 [34]、版本空间代数（VSA）[43]、AST 匹配 [42] 以及合并后静态分析或单元测试 [12, 13] 得到形式化研究。然而，PL 技术作用于千字节级的语法树，而湖仓表跨越数千个云对象、包含数亿至数十亿行数据，在合并时扫描数据文件会带来高昂的 S3 API 延迟与流量成本 [15]。检验写入是否触及读者谓词所选中行的核心思想源于谓词锁 [16]、精度锁 [24] 以及乐观读/扫描集验证 [25, 26]，但这些方法均针对共享同一数据库的短事务设计。目前缺失的是一种在两个长生命周期分支各自提交后、无需读取底层数据文件即可完成事后验证的机制。为此，我们围绕以下四项系统指标评估湖仓分支合并：
- **$M_1$（$W_1$–$W_4$ 上的语义正确性）**：对跨分支语义冲突（$W_3$）与模式冲突（$W_4$）实现 100% 召回率，对热点碰撞实现结构化隔离（$W_2$），并在共享文件上保持 0% 虚假回滚率（$W_1$）。
- **$M_2$（$W_2, W_4$ 上的低延迟合并元数据计算）**：使三路差分与合并 CPU 耗时仅随分支增量规模扩展，而与文件总数（$W_4$）、DAG 历史深度（$W_4$）或争用率 $\rho$（$W_2$）解耦。
- **$M_3$（$W_1, W_4$ 上的云成本效率）**：将 S3 API 请求数约束在 $O(\Delta_{\text{manifest}})$，无需整文件 CoW 重写即可保持 $\text{WAF} \approx 1$。
- **$M_4$（$W_1$ 上受控的合并后读取开销）**：在后台压缩执行前，保持合并快照上的高吞吐分析扫描性能。

为了同时满足 $M_1$–$M_4$，SemLake 融合了三项核心设计机制：
1. **零拷贝物理对齐（$W_1, W_4 \to M_3, M_4$）**：基于位置 Roaring 删除向量（DVs）[5, 31] 与增量清单表示行级变更，将共享文件并发更新编译为位图按位并集与单个增量 Parquet 文件追加。
2. **元数据级语义与模式验证（$W_3, W_4 \to M_1, M_2$）**：每次提交写入一个紧凑 JSON 摘要，记录行操作、模式变更、被删行的删除前像、修改行的分叉与顶端值以及从 `SELECT` 和 `DELETE` 语句提取的 SQL 谓词。合并时，SemLake 通过代数剪枝搜索定位最近公共祖先（LCA），重放分叉以来的非合并提交，在元数据时间内检验静态谓词可满足性，并在静态分析无法排除重叠时直接基于摘要中记录的行值评估谓词。
3. **结构化冲突隔离（$W_2 \to M_1, M_2$）**：将真实单元格写碰撞保存在目录元数据的 VSA 选择节点 [43] 中，避免引发回滚风暴。

最后，在标准湖仓流水线之外，我们评估了高并发自主智能体集群（$W_{\text{swarm}}$）[4, 20, 28, 41]。当 $N$ 个 AI 智能体并发分叉共享表、执行混合了 $W_1, W_2, W_3$ 的操作并通过目录比较并交换（CAS）竞争推进 `main` 时，SemLake 将失败的 CAS 竞争转化为结合组提交的服务端三路语义合并。

本文的主要贡献包括：
1. **统一三路合并模型**：形式化定义了对应 $W_1$–$W_4$ 的四项准则（不相交收敛、VSA 热点隔离、擦除安全合并与模式子类型兼容性），并证明擦除安全性与双分支可串行化（$B_6$）彼此不可比（第 3 节）。
2. **双层谓词验证器**：设计了合取 SQL 片段 $\mathcal{F}$ 上的元数据级静态重叠分析器，并结合对已记录行值的精确检查，在不读取数据文件的前提下消除误报（第 4 节）。
3. **DAG 重放与理论上下界（$M_1$–$M_4$）**：提出了菱形提交 DAG 上的精确分叉重放算法与 Roaring DV 对齐机制，并给出正确性（$M_1$）、延迟（$M_2$）、S3 API 成本（$M_3$）及合并后扫描开销（$M_4$）的形式化分析（第 4、5 节）。
4. **资源受限条件下的原型实现与混合评测平台**：基于 Parquet、Roaring 位图、DuckDB 与 SQLGlot 实现 SemLake，结合 S3 成本/延迟模型、1,000 文件真实 Amazon S3 测试、原生 Dolt/`delta-rs` 基线及智能体集群仿真器（第 6 节）。
5. **实验评估**：在 $W_1$–$W_4$、77 组 TPC-H 分支对、SF 1/SF 10 扫描与 $W_{\text{swarm}}$ 上对比 $B_1$–$B_6$，客观刻画系统的性能收益与适用边界（第 7 节）。

## 2 背景与研究动机 (Background and Motivation)

### 2.1 湖仓存储、删除向量与云存储成本
Delta Lake [6]、Apache Iceberg [5] 与 Apache Hudi [23, 35] 等开放湖仓表格式在云对象存储的不可变 Parquet 文件之上构建事务性元数据层 [21, 40]。由于 S3 对象不可就地修改，早期系统采用写时复制（CoW）执行行级 `UPDATE` 与 `DELETE`，导致高昂的写放大（$\text{WAF} \gg 1$）[10]。Durner 等人 [15] 指出，元数据密集型云存储操作的性能与账单主要受制于 API 请求延迟（每次调用 30–100 ms）与按次请求计费（每 1,000 次 `PUT`/`LIST` 收费 \$0.005，每 1,000 次 `GET` 收费 \$0.0004）。为此，Okolnychyi 等人 [31]、Iceberg v3 [5] 与 Delta Lake 删除向量 [27] 采用结合位置删除向量（Positional DVs）的读时合并（MoR）：DV 是关联至基础 Parquet 文件的压缩 Roaring 位图，标记已删除或被取代行的零基偏移；更新操作在基础文件 DV 中置位旧偏移并将新记录追加至小型增量 Parquet 文件。Iceberg v3 同时引入稳定的行血缘标识符（`__row_id`）以跨更新追踪逻辑行身份。

### 2.2 问题分类体系（$W_1$–$W_4$）与评估指标（$M_1$–$M_4$）
多分支协同引入了分支-执行-合并生命周期 $T_0 \xrightarrow{\text{Branch}} (T_A, T_B) \xrightarrow{\text{Execute}} (T_A', T_B') \xrightarrow{\text{Merge}} T_M$。我们围绕四项指标对 $W_1$–$W_4$ 评分：$M_1$ 为 $W_3, W_4$ 上的召回率与精确率、$W_2$ 上的单元格碰撞隔离以及 $W_1$ 上的虚假回滚率（FAR，目标 0%）；$M_2$ 为跨清单深度、DAG 深度与争用率 $\rho$ 的三路合并延迟；$M_3$ 为 S3 API 请求数、美元成本与写放大因子（WAF，目标 $\approx 1$）；$M_4$ 为压缩前合并快照 $T_M$ 上的 DuckDB TPC-H 相对扫描开销（局部更新目标 $<8\%$）。

## 3 形式化数据模型与三路合并准则 (Formal Data Model and Three-Way Merge Invariants)

### 3.1 快照 DAG、提交摘要与分支增量
- **定义 3.1（表快照）**：$T = (\text{id}, P, S, \rho, \Phi)$，其中 $P$ 为父快照列表（$|P| \in \{0, 1, 2\}$），$S$ 为模式，$\rho$ 为存活行 ID 到列值记录的映射，$\Phi$ 为文件描述符映射 $(k_{\text{obj}}, \text{size}, \text{token}, \text{DV})$。每个快照具有代数 $\text{gen}(u) = 0$（若 $P(u)=\emptyset$）或 $1 + \max_{p \in P(u)} \text{gen}(p)$。
- **定义 3.2（分叉点）**：$T_0 = \text{LCA}(T_A, T_B) = \arg\max_{u \in \text{anc}(T_A) \cap \text{anc}(T_B)} \text{gen}(u)$。
- **定义 3.3（提交摘要与折叠分支增量）**：每个非合并提交 $c$ 记录摘要 $\delta(c) = (\text{ops}_c, S_c, \Pi_c, \sigma_c)$，其中 $\sigma_c$ 保存被删行在删除前一刻的前像记录。按拓扑序折叠 $\mathcal{C}(T_0, T_B) = \text{anc}(T_B) \setminus \text{anc}(T_0)$ 得到分支增量 $\Delta_B = (W(B), D(B), S_B, \Pi(B))$。

**表 2：SemLake 针对 $W_3$ 支持的五类谓词及其三路冲突判定规则。**

| 谓词类别 | 附加来源 | 代表性示例 | 三路冲突规则 ($\Delta_A$ vs. $\Pi_B$) |
| :--- | :--- | :--- | :--- |
| `reads_where`($\varphi_R$) | 查询 / 聚合提交 ($W_3$) | `kind = 'vip' AND value >= 10` | 若与 $\Pi(A)$ 中的 `deletes_where`($\varphi_D$) 满足 $\text{Overlap}(\varphi_D, \varphi_R)$ 且未被被删行值检查排除，或 $\text{ops}_A$ 中的更新/插入使某行跨越 $\varphi_R$ 边界或在 $\varphi_R$ 内部修改了查询引用的列，则判定冲突。 |
| `deletes_where`($\varphi_D$) | 删除 / 清理提交 ($W_3$) | `l_shipdate < 19930201` | 声明删除操作的选择范围，与 $\Pi(B)$ 中的每个 `reads_where`($\varphi_R$) 对称检验。 |
| `rows_live`($I$) | 点查 / 血缘提交 ($W_3$) | $I = \{101, 102, 105\}$ | 若对方分支删除了列表中的任意行标识符（$D(A) \cap I \neq \emptyset$），则判定冲突。 |

| `domain`($\varphi_{\text{dom}}$) | 不变式 / 策略提交 ($W_3$) | `value >= 0` | 若 $\text{ops}_A$ 中的 `insert` 或 `update` 赋予的列值违反 $\varphi_{\text{dom}}$，则判定冲突。 |

### 3.2 跨越 $W_1$–$W_4$ 的四项三路合并准则
1. **准则 1（$W_1$：不相交行与列收敛）**：单侧修改或两侧相同修改直接采纳；对同一行不相交列集的并发更新可交换并合并为 $\rho_0(r) \oplus \Delta_A(r) \oplus \Delta_B(r)$。
2. **准则 2（$W_2$：基于 VSA 的热点单元格碰撞隔离）**：对同一行同一列赋予不同值 $v_A \neq v_B$（或更新与删除冲突）时，封装为 VSA 选择节点 `choice`$(r, c, [(A, v_A), (B, v_B)]) \in \mathcal{V}_M$，其余非冲突列正常收敛。
3. **准则 3（$W_3$：跨分支谓词保持）**：校验表 2 中的五类谓词；`domain` 谓词仅验证自 $T_0$ 以来的新写入赋值，不因 $T_0$ 中的历史遗留数据报错。
4. **准则 4（$W_4$：双向模式子类型兼容性）**：支持新增可空列与无损数值类型拓宽（$\texttt{int32} \prec_{\text{type}} \texttt{int64} \prec_{\text{type}} \texttt{double}$），统一为 $S_M(a) = \sup_{\preceq_{\text{type}}}(\tau_A(a), \tau_B(a))$。

### 3.3 擦除安全合并准则对比可串行化（$W_3$ vs. $B_6$）
**定义 3.5（擦除安全合并 Purge-Safe Merge）**：设 $T_A, T_B$ 的分叉点为 $T_0$。若对 $(X, Y) \in \{(A, B), (B, A)\}$ 对称满足以下四项条件，则称 $T_M = \text{merge}(T_0, T_A, T_B)$ 是擦除安全的：
1. **读-删安全**：对任意 $\texttt{reads\_where}(\varphi_R) \in \Pi(Y)$ 与每条被删行 $r \in D(X)$，其在分叉时的值与删除时刻的前像均不满足 $\varphi_R$，即 $\rho_0(r) \not\models \varphi_R$（若 $r$ 在 $T_0$ 中存在）且 $\sigma_X(r) \not\models \varphi_R$；
2. **存活行与外键保持**：对任意 $\texttt{rows\_live}(I)$ 或 $\texttt{foreign\_key}(I) \in \Pi(Y)$，$D(X) \cap I = \emptyset$；
3. **值域不变式保持**：对任意 $\texttt{domain}(\varphi_{\text{dom}}) \in \Pi(Y)$ 及 $(r, v) \in \text{ops}_X$，$v \models \varphi_{\text{dom}}$；
4. **更新与插入下的读取稳定性**：对任意 $\texttt{reads\_where}(\varphi_R) \in \Pi(Y)$ 以及被分支 $X$ 更新或插入（且未删除）的每条行 $r$（顶端值为 $\rho_X(r)$），$r$ 在 $\varphi_R$ 下的归属保持不变，即 $\rho_0(r) \models \varphi_R \Leftrightarrow \rho_X(r) \models \varphi_R$（新插入行在 $T_0$ 视为不满足 $\varphi_R$），且当 $r$ 满足 $\varphi_R$ 时，$\rho_0(r)$ 与 $\rho_X(r)$ 在查询于 `WHERE` 子句之外引用的投影列集合 $\text{cols}(\varphi_R)$ 上取值一致。

**命题 3.6（擦除安全性 vs. 可串行化 $B_6$）**：擦除安全性与双分支冲突可串行化彼此不可比（incomparable）。存在分支对 $(T_A, T_B)$ 在 SSI（$B_6$）下容许串行序 $T_B \prec T_A$ 却违反擦除安全性；反之，将单元格碰撞保留为 VSA 选择节点的合并满足擦除安全性，但无法等价于任何丢失一侧写入的串行执行序。

## 4 系统架构与合并设计 (System Architecture and Merge Design)

### 4.1 紧凑提交摘要、SQL 谓词提取与 DAG 分叉重放（算法 1）
每次提交写出一个紧凑 JSON 摘要，记录父快照 ID、模式、修改文件的 Roaring DV、行操作、删除前像 $\sigma_c$、分叉/顶端行值、谓词及 VSA 节点。算法 1（`ReplaySinceFork`）获取缓存的 $\mathit{contained} = \text{anc}(b)$，从分支顶端 $t$ 执行后序 DFS 并在进入 $\text{anc}(b)$ 时停止，按拓扑序对 $\text{anc}(t) \setminus \text{anc}(b)$ 中的每个常规提交发起 1 次 `GET` 并折叠；遇到内部合并菱形节点时，通过 `StripPrefix` 剥离内部分叉点 $f = \text{LCA}(p_1, p_2)$ 的共享前缀 $\mathit{folded}[f]$，确保共享历史不被重复计为冲突且中间合并之前的谓词不丢失。

### 4.2 双层语义冲突验证（算法 2：`VerifyMergeSemantics`）
算法 2 对称遍历 $(X, Y) \in \{(A, B), (B, A)\}$，执行四个验证步骤：
1. **第一层静态可满足性求解（`WhereOverlap`）**：当 $\varphi_D, \varphi_R$ 均属于合取片段 $\mathcal{F}$（二元比较、`IN`、`BETWEEN`）时，按列对等值候选集、`!=` 排除点与上下界求交。若任一列不可满足，则在微秒内判定 $\varphi_D \land \varphi_R$ 不可满足，仅需对删除前曾在分支 $X$ 上被修改过的行集合 $\mathit{moved}_X = \{r \in D_X \mid \sigma_X(r) \neq \rho_0(r)\}$ 检查其分叉值 $\rho_0(r)$。
2. **第二层被删行值检查（`AnyMatch`）**：当子句落在 $\mathcal{F}$ 之外（如含 `NOT`、`OR`）或静态区间存在重叠时，算法直接对每条被删行 $r \in D_X$ 的分叉值 $\rho_0(r)$ 与删除前像 $\sigma_X(r)$ 评估 $\varphi_R$（$\mathcal{F}$ 内子句原生求值，其余单表 SQL 子句通过内存 DuckDB 对候选行求值），无需读取任何基础 Parquet 文件。
3. **血缘、外键与值域验证**：检查 $D_X \cap I \neq \emptyset$ 并校验所有 `insert`/`update` 赋值是否满足 $\varphi_{\text{dom}}$。
4. **更新与插入下的读取稳定性检查（`Unstable`）**：算法第 14 行对每条被更新或插入的行 $r \in U_X$ 比较其分叉值 $\rho_0(r)$ 与顶端值 $\rho_X(r)$：若 $r$ 跨越了 $\varphi_R$ 边界，或在两端均满足 $\varphi_R$ 但修改了查询引用的投影列 $\text{cols}(\varphi_R)$，则标记为冲突。

## 5 正确性、复杂度与扫描开销分析 (Correctness, Complexity, and Scan Overhead Analysis)

- **定理 5.1（可靠性 Soundness）**与 **引理 5.2（精确 DAG 重放）**：证明当算法 2 返回 $V = \emptyset$ 时，合并快照 $T_M$ 严格满足定义 3.5 的条件 1–4 及准则 1–4。我们进一步通过 **200 个随机种子**的模糊测试（`tests/test_fuzz.py`，含直接合并与跨中间菱形合并、正反两种合并顺序）对比暴力物化行状态预言机，验证了 0 漏检。
- **合并时间与云 API 复杂度（$M_2, M_3$）**：非合并提交数为 $K$ 时，算法 1 最多发起 $K$ 次 `GET`，算法 2 耗时 $O(|\Pi_A|\cdot|\Pi_B| + |\Delta_{\text{rows}}|)$，物理发布写出 1 个增量 Parquet 文件与 3 个小型 JSON 元数据对象，总 S3 请求数为 $O(K + |\Delta_{\text{files}}|)$，与表总文件数 $N_{\text{files}}$ 解耦。
- **合并后扫描开销上界（$M_4$）**：$T_{\text{scan}}(T_M) = C_{\text{scan}} \cdot (1 + \alpha \cdot \frac{G_{\text{dirty}}}{G_{\text{rg}}})$，压缩盈亏平衡点为 $N_{\text{scans}}^* = \frac{C_{\text{compact}}}{\alpha \cdot C_{\text{scan}} \cdot (G_{\text{dirty}} / G_{\text{rg}})}$。

## 6 系统实现 (Implementation)

在单机学术资源约束下，我们以约 **2,400 行**核心引擎代码（8 个模块：`metadata.py`、`storage.py`、`merge.py`、`verification.py`、`sql_predicates.py`、`reader.py`、`s3store.py`、`baselines.py`）和约 **5,100 行**基准与仿真代码实现了 SemLake。底层数据采用 `pyarrow` Parquet 文件（含 `__row_id`）与 `pyroaring` 32 位位图；分析扫描在 DuckDB 1.5.6 中执行；内存对象存储（`MemoryObjectStore`）与真实 Amazon S3 后端（`s3store.py`）共享相同的 `put`/`get`/`list` 接口并精确统计请求数与字节数。基线 $B_1, B_1\text{R}, B_2, B_6$ 在与 SemLake 相同的快照上执行各自规则（其中 $B_1$ 经真实 `delta-rs` 表交叉验证），$B_3, B_4$ 为同存储后端上的存储布局重实现，$B_5$ 调用原生 Dolt 2.5.0 二进制执行 `dolt merge`。

## 8 局限性与结论 (Limitations and Conclusion)

在有限的单机学术资源下，本研究通过将真实物理存储/查询执行与解析模型及离散事件仿真相结合，在获得客观实验结论的同时也明确了五项适用边界：(1) **云端延迟与基线建模**：Parquet I/O、Roaring 位图、DuckDB 扫描（SF 1 与 SF 10）及 Dolt 合并均为真实物理执行，1,000 文件 `eu-north-1` S3 实验也证实了请求数的精确匹配，但客户端广域网往返使真实 S3 挂钟耗时为解析模型的 3.4–4.5 倍；$B_1, B_1\text{R}, B_2, B_6$ 采用共享快照上的规则模型评估，与分布式集群系统（如 lakeFS、Nessie）的对比留待后续工作。(2) **谓词范围**：条件 4 比较行状态而非最终聚合值，会保守拦截虽修改投影列但未改变聚合结果的更新，且跨表连接与子查询超出了单表行级求值范围。(3) **原型规模与扫描路径**：Python 原型在内存中维护分支行增量（TPC-H 合并对使用 SF 0.01），在 DuckDB 中通过位置掩码连接而非原生 C++ 位图读取器应用 DV，并在未压缩合并间累积增量文件描述符。(4) **跨表合并**：将组提交扩展至多表湖仓事务 [18, 19] 仍有待探索。(5) **声明式读取与前像保留**：可靠性依赖于写入方声明读取谓词，且提交摘要保留了被删行前像，未来可仅保留加密的谓词相关列并定期裁剪历史摘要。

SemLake 将具有形式化可靠性保证的三路语义合并引入分支数据湖仓。通过将紧凑提交摘要上的双层谓词与行值冲突验证同 Roaring 删除向量上的零拷贝物理对齐解耦，SemLake 拦截了文件级与行级合并漏检的跨分支语义冲突，并使对象存储请求数仅随分支增量而非整表规模增长。
